# 合并与冲突

`mergeNotes(existing, incoming)` 按 id 合并。不存在的 id 添加到集合；同一 id 只有 incoming.updatedAt 严格晚于现有版本时才替换。时间相同保留 existing，因此交换两个参数可能得到不同正文。

重复导入同一份备份是幂等的，不会增加重复笔记。即使同一 id 的输入版本乱序，较新的修订仍会胜出。合并不是正文逐行合并，旧版正文不会被拼接到新版末尾。

修改时间受设备时钟影响。编辑逻辑保证本地修订递增，但两台设备离线编辑仍可能产生相同或错误的时间；合并前保留两份原始备份，避免丢失需要手工取舍的正文。

合并结果最多 1,000 篇。该函数检查对象和数量，调用方在保存前还必须运行 `serializeNotebook` 检查整个结果的 UTF-8 字节容量。两份各自合法的备份，合并后仍可能超过总限制。

遇到冲突时，可以分别用其他编辑器查看原始 JSON 中的 content 和 updatedAt，选定需要保留的正文后通过正常编辑产生新的修订。不要只依据 exportedAt 判断内容新旧。
